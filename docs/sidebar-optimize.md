你观察得很准。收缩态现在的问题是**「顶部在导航，底部也在导航，中间夹了一堆操作按钮」**，导致 48px 的窄条里塞了两套语义重叠的图标。

核心矛盾：**收缩态应该只做一件事——「快速切换模块/接口」，而不是把展开态的所有功能平铺成图标。**

## 一、当前问题拆解

| 位置 | 现有图标 | 问题 |
|------|----------|------|
| **顶部** | 闪电、D、1、U、T、等、新 | 这是「模块/分组导航」，没问题 |
| **底部** | +、文件夹、搜索、+、齿轮、垃圾桶 | 和顶部语义打架，且两个「+」让人困惑 |

**重复点**：
- 底部「文件夹」图标 vs 顶部各模块图标 → 都是入口，用户不知道点哪个
- 底部「搜索」图标 vs 顶部搜索框（展开态）→ 收缩态搜索应该直接唤起全局搜索浮层，不需要常驻底部
- 两个「+」图标 → 一个新建请求、一个新建大类？图标完全一样无法区分

## 二、收缩态重新设计：窄条只做「切换」，操作全部上浮

### 方案 A：极简导航条（推荐）

```
┌────────┐
│  ⚡     │  ← 点击展开/收起侧边栏（hover 显示 Tooltip"接口目录"）
├────────┤
│  ●D    │  ← Default 模块（当前选中，蓝色竖线指示）
│  ①     │  ← 分组1
│  ■U    │  ← Ungrouped（hover 显示完整名称）
│  T     │
│  等    │
│  新    │
├────────┤
│  ⋮     │  ← 更多操作：新建 / 环境变量 / 回收站 / 设置（点击弹出菜单）
│        │
│  [+ ]  │  ← 悬浮新建按钮（FAB，主色圆形，hover 展开二级菜单）
└────────┘
        ↑
    宽度 48px，仅保留 8 个图标位
```

**改动点**：
- **底部只留 2 个图标**：「更多（⋮）」和「新建（+）」
- **搜索移除**：收缩态不需要搜索框占位，直接 `Ctrl+K` 或点击顶部闪电后展开搜索
- **环境变量/回收站/设置**：全部收进「更多」菜单，避免和展开态的底部按钮一一对应

### 方案 B：上下文感知底部（如果坚持多按钮）

```
┌────────┐
│  ⚡     │
├────────┤
│  ●D    │
│  ①     │
│  ■U    │
│  T     │
│  等    │
│  新    │
├────────┤
│  🔍    │  ← 唤起全局搜索浮层（居中弹出）
│  ⚙️    │  ← 直接打开环境变量抽屉（从右侧滑出，不展开侧边栏）
│  🗑    │  ← 回收站（抽屉）
│  ➕    │  ← 新建（下拉菜单：请求/模块/分组/导入）
└────────┘
```

这个方案的问题：**4 个底部按钮在 48px 宽里太挤**，手机端可以，桌面插件没必要。

## 三、关键交互细节

### 1. 模块图标（顶部列表）优化

**当前**：用首字母做图标（D、U、T），颜色区分，但「等」「新」这种中文字首字母很丑。

**优化**：
- 允许用户给模块/分组设置 **Emoji 图标**（🚀、📦、🔒），收缩态直接显示 Emoji，辨识度极高
- 如果没有设置，取前 2 个字符（如「默认」显示「默」）或自动生成色块 + 首字母
- **当前选中模块**：右侧加 3px 主色竖线（你现在的紫色边框可以保留，但改成左侧竖线更符合视觉流向）

├────────┤

## 四、展开/收缩的过渡动画

**当前**：直接切换，有点生硬。

**优化**：

| 状态 | 宽度 | 动画 | 内容策略 |
|------|------|------|----------|
| **展开** | 220px | 200ms ease-out | 显示完整树 + 文字 + 底部按钮 |
| **收缩** | 48px | 150ms ease-in | 只显示图标，文字用 Tooltip 补全 |
| **悬浮展开** | 220px | 0ms（即时） | 鼠标 hover 在收缩态上时，临时浮出完整面板，移开收回 |

**悬浮展开** 是浏览器插件侧边栏的经典交互：
- 鼠标移到 48px 窄条上 → 右侧浮出 220px 的完整面板（不挤压中间内容区）
- 鼠标移出 → 自动收回
- 点击闪电图标 → 固定展开（挤压中间内容区）
